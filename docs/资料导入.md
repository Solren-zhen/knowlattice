# 资料导入：格式 → 入口 → 落地 → 联动

> 本文描述的是**当前代码的真实行为**（每一行都对照过入口组件与 `src/core` 里的实现）。
> 路径都是仓库相对路径。
>
> 一条贯穿全部入口的原则：**能识别的字段才映射，认不出来就报「缺什么」，不做任何猜测**；
> 导入前不认识的文件不会被改动一个字节。

## 一、总表

| 格式 | 界面入口（点哪里） | 后缀 | 落地为 | 落地后自动获得的能力 |
| --- | --- | --- | --- | --- |
| 本应用题库 JSON | 左侧导航轨「题库练习」→ 面板头部「导入题库」→「题库文件 (.json)」（或把 JSON 粘进下方输入框 →「粘贴导入」） | `.json` | **题库**（浏览器本地 IndexedDB，键 `knowlattice-qbanks`；**不进笔记库**） | 组题/整库练习；逐题历史、正确率与待复习（`core/qbankStats`，含 FSRS 排程）；答错且能关联到笔记时进错题本（`core/mistakes`，关联走 `note` 字段或 `题库/<源>/<学科>/<章节>.md` 反查）；每个题库「更多 → 导出 Anki」（`core/anki` 的 `bankToAnki`，`.txt`）；练习页「问 AI 讲这题」（把题干/选项/正解/我的选择交给 AI）。题库本身不进复习卡队列 |
| 万川式短键题库 | 同上一行（旧解析拿不到题目时**自动介入**，无需改格式） | `.json` | 题库 | 同上；导入报告里会写明「识别为「短键题库（万川医考风格）」（置信度 N%）」与跳过条目 |
| 窦起心搏式富文本题库 | 同上 | `.json` | 题库 | 同上（`jiexiArr` 一题多解析、`knowledge` 多章节、选项图片都会带进来） |
| Anki 牌组包 | 笔记树右上角 **⋯ →「导入 Anki 牌组 (.apkg/.txt)」** | `.apkg` | **笔记**，固定落在 `imported/anki/<标题>.md` | 复习卡（L1）、全库 Anki 导出（含 Cloze 卡型）、全文检索/大纲、错题归位、可被 AI 引用；`{{c1::答案::提示}}` 会转成本项目认的 `{{答案}}` 挖空 |
| Anki「导出为 .txt」 | 同上（同一入口，按后缀分流） | `.txt` / `.tsv` | 笔记（同 `imported/anki/`） | 同上 |
| 症状→疾病数据集 | 笔记树 **⋯ →「导入数据集 (.json)」** | `.json` | **笔记**（库根，`<症状名>.md`） | 复习卡、Anki 导出、检索/大纲、AI 引用；疾病名写成本项目双链 `[[疾病名]]`（允许指向还不存在的笔记，之后可补） |
| 口诀/记忆术数据集 | 同上 | `.json` | 笔记（库根，`<关键词>.md`） | 同上；正文里的「口诀」行可直接做挖空复习卡 |
| 术语表数据集 | 同上 | `.json` | 笔记（库根，`<中文名>.md`） | 同上（中英对照便于检索与对照背诵） |
| 字幕 | 笔记工具栏的「挂音频/字幕」按钮（`aria-label="给当前笔记挂音频或字幕"`，可多选） | `.srt` / `.vtt` | **附件**（`_attachments/`）+ 挂载关系记在本机 localStorage（`knowlattice-note-media`）；字幕文本不直接成笔记，而是经播放条的「转成复习卡」把**挖空后**的字幕写进当前笔记的 `## 字幕复习卡` 小节（同标题小节是幂等替换，连点两次不会多一份） | 写进笔记后自动获得笔记的全部联动（复习卡/Anki 导出/检索/AI 引用）；逐句字幕还能与音频同步高亮与点句回跳（`core/subtitle`、`views/MediaTrack.tsx`） |

## 二、最小可用合成示例

以下全部是**占位内容**（甲/乙/丙、term-alpha），不含任何真实题目或资料。

### 1. 本应用题库 JSON（`题库练习 → 导入题库 → 题库文件 (.json)`）

```json
[
  {
    "stem": "题干甲？",
    "options": ["选项甲", "选项乙", "选项丙"],
    "answer": 0,
    "explanation": "解析甲。",
    "chapter": "章节甲",
    "note": "笔记甲"
  }
]
```

也可以是 `{"name": "题库甲", "questions": [ … ]}`（`name` 会当题库名，没有就用文件名）。

### 2. 万川式短键题库（同一个 `.json` 入口，自动识别）

```json
[
  { "s": "题干乙？", "o": ["选项丁", "选项戊"], "a": "A", "t": 1, "x": "解析乙" },
  { "s": "共用题干丙？", "sub": [
      { "s": "小问甲？", "o": ["选项己", "选项庚"], "a": 1, "t": 1 }
  ] }
]
```

### 3. 窦起心搏式富文本题库（同一个 `.json` 入口，自动识别）

```json
[
  {
    "title": [{ "type": 1, "content": "题干丁？" }],
    "options": [
      { "val": "A", "oldtext": "选项辛", "content": [{ "type": 1, "content": "选项辛" }] },
      { "val": "B", "oldtext": "选项壬", "content": [{ "type": 1, "content": "选项壬" }] }
    ],
    "answer": ["A"],
    "jiexiArr": { "来源甲": { "analysis": [{ "type": 1, "content": "解析丙" }] } },
    "knowledge": "章节乙"
  }
]
```

### 4. Anki `.apkg`

在 Anki 里「导出 → Anki 牌组包 (.apkg)」，**不要**导出成新版压缩集合（`collection.anki21b`；本项目会明确报错并让你按旧格式重导，不会静默返回空结果）。

### 5. Anki「导出为 .txt」

制表符分隔，每行 `正面<TAB>背面[<TAB>标签]`（标签里可写 `章节:章节甲`）：

```text
正面甲	背面甲	章节:章节甲
正面乙	背面乙
```

### 6. 症状→疾病数据集

```json
{
  "entries": [
    { "symptom": "症状甲", "diseases": ["疾病甲", "疾病乙"], "category": "系统甲" },
    { "symptom": "症状乙", "diseases": "疾病丙、疾病丁" }
  ]
}
```

### 7. 口诀数据集

```json
{
  "specialty": "专科甲",
  "source_note": "来源说明甲",
  "entries": [
    { "keyword": "口诀甲", "mnemonic": "口诀文本甲", "composition": "组成甲", "function": "功用甲", "indication": "主治甲" },
    { "keyword": "口诀乙", "category": "分类乙", "detail": "内容乙" }
  ]
}
```

### 8. 术语表数据集

```json
{
  "terms": [
    { "en": "term-alpha", "zh": "术语甲", "note": "备注甲" },
    { "en": "term-beta", "zh": "术语乙" }
  ]
}
```

### 9. 字幕 `.srt`

```text
1
00:00:00,000 --> 00:00:03,000
第一句甲（{{挖空甲}}）为正常

2
00:00:03,000 --> 00:00:06,000
第二句乙。
```

（上面的 `{{挖空甲}}` 是「转成复习卡」生成的结果，不是要你手写：源字幕写普通句子即可——
括号内内容、`数字+单位`、英文术语由 `subtitleToCardText` 自动挖空。`{{}}` 是本项目唯一的挖空标记，
复习界面据此遮答案、翻面还原。）

## 三、字段对照表

### 题库 JSON（本应用格式；这些也是唯一会被写进题库的字段名）

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `stem` | 题干 | 必填；兼容 `question` / `题干` / `题目` |
| `options` | 选项数组 | ≥2 项即选择题；兼容 `choices` / `选项`；缺省即简答题 |
| `answer` | 正确答案 | 下标 / `"A"` / 选项原文；多选可写连续字母串 `"AC"` |
| `answers` | 多选答案集合 | 只在真的多选时出现；给了它就按「全对才算对」判分 |
| `explanation` | 单条解析 | 兼容 `解析` / `解释` |
| `explanations` | 一题多套解析 `[{source, text}]` | 兼容 `jiexiArr`；复习时可切换来源对照 |
| `chapters` | 一题多章节 | 兼容 `chapterList` / `多章节` / `知识点`；`chapter` 仍是主章节 |
| `groupStem` | 共用题干（A3/A4 病例原文） | 每个小问仍是独立的一道题 |
| `image` | 题干图片（vault 相对路径） | 兼容 `img` / `图片` / `图片路径` / `题图` |
| `optionImages` | 逐选项图片，下标对齐 `options` | 空位写 `null`；兼容 `选项图片` / `optionImgs` |

### Anki 的章节标记

标签里写 `章节:生理学` / `chapter:生理学` / `科目:生理学`（`键:值`，Anki 标签不允许空格，这种写法正好合法）。
**只有显式写了这个标记才会带章节**：光看标签文字猜不出哪个是章节，猜错会让统计热力图分错组，而分错组的图看起来完全正常。

### 数据集候选字段名（中英混用、单复数混用都认）

| 语义 | 候选键 |
| --- | --- |
| 列表本体 | 顶层数组，或对象里的 `entries` / `列表` / `items` / `data` / `list` / `records` / `rows` / `terms` / `术语` / `词条` |
| 症状 | `symptom` / `症状` |
| 疾病 | `diseases` / `diseasesRaw` / `疾病`（数组或「、，;」分隔的字符串） |
| 口诀 | `keyword` / `关键词` / `名称`；`mnemonic` / `口诀` / `助记`；`detail` / `内容` / `详情` |
| 口诀分项 | `composition` / `组成`、`function` / `功用` / `功效`、`indication` / `主治` / `适应症` / `适应证`、`source` / `出处` / `来源` |
| 术语 | `en` / `英文`、`zh` / `中文`、`note` / `备注`；嵌套词条列表 `terms` / `术语` / `词条` |
| 分类/章节 | `category` / `分类` / `系统` / `专科`；术语还用 `title` / `标题` 兜底 |
| 外层元信息 | 口诀数据集允许 `specialty` / `专科` / `分类` 与 `source_note` / `来源` / `出处` 放在最外层 |

## 四、识别不出来时会怎样

**不做任何猜测，也不写任何东西**，只把「缺什么」报出来：

- **数据集**（`⋯ → 导入数据集`）：直接报 `detectDataset` 给出的依据，例如
  「读到 1 条记录，但没有命中任何一类数据集的字段组合；症状→疾病：需要 symptom/症状 与 diseases/diseasesRaw/疾病；口诀：需要 keyword/关键词/名称…；术语：需要 en/英文 与 zh/中文…」。
- **题库**（自动形状映射）：报告区（`.quiz-import-report`，`role="status"`）里逐条写明缺的字段，例如
  「没找到题干字段（期望 stem/question/题干/题目/s/title/tktitle）」「没找到选项字段（期望 options/选项/o/choices）」；
  形状认出来但逐条都映射不成题时，也会给出「可导入 0 题；跳过 N 条，例：第 1 条 …」。
- **Anki**：`.apkg` 不是合法包、缺 `collection.anki2`、是 `collection.anki21b` 压缩库、没有 `notes` 表……每一种都有明确的中文说明与「该怎么办」（例如「请在 Anki 里重新导出并勾选旧格式」）。

同时明确：**原始文件不会被修改，也不会被上传到任何地方**。所有解析都在本机完成（浏览器里读 `File.text()` / `arrayBuffer()`），
导入结果写进本机的 vault 文件夹或本机 IndexedDB——本地优先，没有服务端。

## 五、合规与来源标注

- 所有导入的**笔记**都由 `src/core/importToVault.ts` 统一组装，每篇强制写入 frontmatter 的 `source:` 字段（复习界面、统计面板、导出、分享时都看得见），内容形如
  `source: Anki 导入（Basic，来自 基础卡.apkg）`、`source: 数据集导入（症状→疾病对照，来自 数据集甲.json）`。
  这是**预防措施，不是装饰**：让「这份资料从哪来」永远跟着笔记走，不会被误当成使用者自己的原创。
- 导入器**只搬运格式、不改写内容**：字段名换成笔记里的中文标签、疾病名包成 `[[双链]]`，链接文字仍是原名，出问题可以逐字对照源文件。
- 本项目**不随应用分发任何第三方资料**，也不内置任何题库/数据集内容；文件一律由使用者自己提供。
- 导入的内容**只存在使用者本机**，不上传、不同步到任何服务器、不随应用分发、不做二次分发。
- 导入内容的**版权归原始权利人**，仅限个人学习使用；需要分享、再分发或商业使用，请自行获得权利人许可。
- 使用者在导入前应自行确认有权使用那份文件（尤其是别人分享的题库、付费课程的讲义与题目）。
