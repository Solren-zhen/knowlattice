# 故障排查指南

> KNOWLATTICE 常见问题诊断与解决方案

## 安装与启动问题

### ❌ `npm install` 失败

**现象**：安装依赖时报错 `ERESOLVE unable to resolve dependency tree`

**解决方案**：
```bash
# 1. 清理缓存
npm cache clean --force

# 2. 删除旧文件
rm -rf node_modules package-lock.json

# 3. 重新安装（使用 legacy peer deps）
npm install --legacy-peer-deps
```

如果仍然失败，检查 Node.js 版本：
```bash
node --version  # 需要 18.x 或更高
```

---

### ❌ `npm run dev` 启动后白屏

**可能原因**：
1. 端口被占用（默认 5173）
2. 浏览器缓存问题
3. 依赖版本冲突

**解决方案**：
```bash
# 1. 检查端口占用
netstat -ano | findstr :5173  # Windows
lsof -i :5173                 # macOS/Linux

# 2. 强制刷新浏览器
Ctrl + Shift + R (Windows/Linux)
Cmd + Shift + R (macOS)

# 3. 清理构建缓存
npm run clean  # 会删除 dist/ 和 .vite/
npm run dev
```

---

### ❌ Tauri 打包失败

**现象**：`npm run pack` 报错 `Rust toolchain not found`

**解决方案**：
```bash
# 1. 安装 Rust（如果未安装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. 确认安装成功
rustc --version
cargo --version

# 3. 安装 Tauri CLI 依赖（Windows 需要）
# 参考：https://tauri.app/v1/guides/getting-started/prerequisites

# 4. 重新打包
npm run pack
```

**Windows 特殊要求**：
- 安装 Visual Studio Build Tools
- 安装 WebView2 Runtime

## 数据与存储问题

### ❌ 笔记无法保存

**现象**：编辑后刷新页面，内容丢失

**诊断**：
1. 打开浏览器控制台（F12）
2. 切换到 Console 标签
3. 查看是否有红色错误信息

**常见原因与解决方案**：

#### 1. IndexedDB 存储已满
```javascript
// 控制台查看存储使用情况
navigator.storage.estimate().then(console.log)
```
如果 `usage` 接近 `quota`，说明存储已满：
- 删除不需要的附件（特别是大图片）
- 清理浏览器缓存
- 迁移到文件夹模式

#### 2. 浏览器隐私模式
- 隐私模式下 IndexedDB 不持久化
- 退出隐私模式或切换到文件夹模式

#### 3. 文件系统权限不足
（文件夹模式）

检查笔记库文件夹权限：
```bash
# macOS/Linux
ls -la /path/to/notes

# Windows（PowerShell）
Get-Acl "C:\path\to\notes" | Format-List
```

确保当前用户有读写权限。

---

### ❌ 数据丢失或损坏

**紧急恢复步骤**：

#### 浏览器模式
1. **检查历史快照**：
   - 侧边栏 → "历史" → 查看自动快照
   - 选择最近的版本恢复

2. **导出残留数据**：
   ```bash
   # 打开浏览器控制台（F12）
   # 执行以下代码导出 IndexedDB 数据
   ```

3. **重建索引**：
   - 设置 → 高级 → "重建搜索索引"
   - 等待重建完成（可能需要几分钟）

#### 文件夹模式
1. **检查备份**（如果启用了自动备份）：
   - 笔记库根目录 → `.backups/` 文件夹
   - 找到最近的备份文件

2. **Git 恢复**（如果用 Git 管理）：
   ```bash
   cd /path/to/notes
   git log --all --oneline  # 查看历史记录
   git checkout <commit-id> -- <file>  # 恢复单个文件
   ```

3. **系统快照恢复**：
   - Windows：文件属性 → "以前的版本"
   - macOS：Time Machine
   - Linux：`~/.local/share/Trash/` 回收站

---

### ❌ 同步冲突

**现象**：用坚果云/OneDrive 同步后，笔记内容混乱或重复

**原因**：多设备同时编辑同一笔记

**解决方案**：
1. **手动合并冲突文件**：
   - 同步工具通常会生成 `笔记 (冲突副本).md`
   - 手动对比并合并内容

2. **启用锁定机制**（计划中功能）

3. **临时方案**：
   - 设备 A 编辑时，设备 B 不打开应用
   - 或使用 Git 管理（有冲突提示）

## AI 助手问题

### ❌ AI 回复 "API 错误"

**诊断步骤**：
1. 打开浏览器控制台（F12）
2. 切换到 Network 标签
3. 重新发送消息，查看 API 请求

**常见错误与解决方案**：

#### 401 Unauthorized
- **原因**：API 密钥错误或过期
- **解决**：重新填写正确的 API 密钥

#### 429 Too Many Requests
- **原因**：请求频率超限
- **解决**：等待 1 分钟后重试，或升级 API 套餐

#### 500 Internal Server Error
- **原因**：API 服务商故障
- **解决**：稍后重试，或切换到备用 API

#### Network Error / CORS
- **原因**：网络问题或代理配置错误
- **解决**：
  ```bash
  # 检查网络连接
  ping api.openai.com
  
  # 如果用代理，确认代理设置正确
  echo $HTTP_PROXY
  echo $HTTPS_PROXY
  ```

---

### ❌ AI 回答不准确或乱编

**解决方案**：
1. **上传教材 PDF**：
   - 侧边栏 → 设置 → AI 助手 → 上传教材
   - 上传后在对话中要求"引用教材原文"

2. **使用更强的模型**：
   - GPT-4 > GPT-3.5
   - Claude 3.5 Sonnet > Claude 3 Haiku

3. **明确要求**：
   - ❌ "讲讲心衰"
   - ✅ "根据《内科学》第 10 版，解释慢性心衰的 NYHA 分级"

4. **核对关键信息**：
   - 药物剂量、诊断标准等务必查阅教材
   - AI 回答仅供参考

---

### ❌ 教材 PDF 上传失败

**可能原因**：
1. **文件是扫描版**：
   - 检查：用 Adobe Reader 打开，能否复制文本
   - 解决：先用 OCR 工具（如 ABBYY FineReader）识别文字

2. **文件过大**（> 100MB）：
   - 用 PDF 压缩工具减小文件大小
   - 或分章节上传

3. **文件名含特殊字符**：
   - 重命名为纯英文或拼音（如 `neikeXue_v10.pdf`）

4. **浏览器内存不足**：
   - 关闭其他标签页
   - 重启浏览器后重试

## 性能问题

### ⚠️ 应用卡顿或响应慢

**诊断**：
1. 打开控制台（F12）→ Performance 标签
2. 点击 Record → 操作一会儿 → Stop
3. 查看耗时最长的操作

**常见原因与优化**：

#### 1. 笔记数量过多（> 1000 篇）
- **症状**：打开笔记列表慢
- **解决**：
  - 按文件夹分类整理
  - 归档旧笔记（移到单独的归档库）

#### 2. 单篇笔记过大（> 50KB）
- **症状**：编辑器输入卡顿
- **解决**：
  - 拆分为多篇笔记
  - 移除不必要的大段代码块

#### 3. 图片过多或过大
- **症状**：滚动时卡顿
- **解决**：
  - 压缩图片（推荐用 TinyPNG）
  - 转为外链（如图床）

#### 4. 搜索索引未优化
- **症状**：全库搜索慢
- **解决**：
  - 设置 → 高级 → "重建搜索索引"

---

### ⚠️ 内存占用过高

**检查内存使用**：
```bash
# 打开控制台（F12）→ Memory 标签
# 点击 "Take snapshot" 查看内存占用
```

**优化建议**：
1. 关闭不用的笔记标签页
2. 限制知识图谱显示的节点数（设置 → 图谱 → 最大节点数）
3. 禁用实时预览（设置 → 编辑器 → 关闭预览）
4. 重启应用释放内存

## 显示问题

### ❌ 界面错位或样式异常

**解决方案**：
```bash
# 1. 清除浏览器缓存
# Chrome: Ctrl + Shift + Delete → 清除缓存图像和文件

# 2. 强制刷新
Ctrl + Shift + R

# 3. 重置界面布局
# 设置 → 界面 → "恢复默认布局"
```

---

### ❌ Markdown 渲染异常

**示例**：
- 双链 `[[笔记]]` 不高亮
- 代码块不显示高亮
- 公式不渲染

**解决方案**：
1. **检查语法**：
   - 双链：`[[笔记名]]`（注意是两个方括号）
   - 代码块：三个反引号 + 语言名
   - 公式：`$公式$` 或 `$$公式$$`

2. **禁用冲突的浏览器插件**：
   - 某些广告拦截器会破坏渲染
   - 尝试隐身模式（无插件）测试

3. **更新到最新版本**：
   ```bash
   git pull origin main
   npm install
   npm run dev
   ```

## 3D 解剖图谱问题

### ❌ 3D 模型不显示

**可能原因**：
1. **WebGL 未启用**：
   - 访问 https://get.webgl.org/
   - 如果看到旋转的立方体，说明 WebGL 正常

2. **显卡驱动过旧**：
   - 更新显卡驱动到最新版

3. **浏览器不支持**：
   - 使用 Chrome/Edge/Firefox 最新版
   - Safari 可能有兼容性问题

---

### ⚠️ 3D 渲染卡顿

**优化方案**：
1. 降低模型细节：
   - 右键 → 渲染质量 → "中" 或 "低"

2. 关闭阴影和光照：
   - 设置 → 解剖图谱 → 关闭高级渲染

3. 使用独立显卡（笔记本）

## 测试与开发问题

### ❌ `npm run test` 失败

**解决方案**：
```bash
# 1. 清理缓存
rm -rf node_modules/.vite

# 2. 重新安装依赖
npm install

# 3. 单独运行失败的测试
npm run test -- src/core/__tests__/vault.test.ts
```

---

### ❌ `npm run build` 失败

**常见错误**：

#### TypeScript 类型错误
```bash
# 查看详细错误
npm run build 2>&1 | tee build.log

# 修复后重新构建
npm run build
```

#### 文件路径问题
- Windows 路径用反斜杠 `\`
- 构建脚本中改为 `path.join()` 或 `path.resolve()`

## 预防措施

### 1. 定期备份

**手动备份**：
- 每周导出一次完整数据（`.zip` 文件）
- 文件夹模式可用 Git 自动版本管理

**自动备份**（设置）：
- 设置 → 数据 → 启用自动备份
- 备份频率：每天
- 保留最近 7 天的备份

### 2. 版本管理（文件夹模式）

```bash
cd /path/to/notes
git init
git add .
git commit -m "初始化笔记库"

# 每次编辑后
git add .
git commit -m "更新：心力衰竭笔记"
```

### 3. 定期更新

```bash
# 更新 KNOWLATTICE
git pull origin main
npm install
npm run dev
```
