# 故障排查指南

> KNOWLATTICE 常见问题诊断与解决方案

## 安装与启动问题

### ❌ `npm install` 失败

**现象**：安装依赖时报错 `ERESOLVE unable to resolve dependency tree`

**解决方案**：
```bash
# 1. 清理缓存
npm cache clean --force

# 2. 删除旧文件
rm -rf node_modules package-lock.json

# 3. 重新安装（使用 legacy peer deps）
npm install --legacy-peer-deps
```

如果仍然失败，检查 Node.js 版本：
```bash
node --version  # 需要 18.x 或更高
```

---

### ❌ `npm run dev` 启动后白屏

**可能原因**：
1. 端口被占用（默认 5173）
2. 浏览器缓存问题
3. 依赖版本冲突

**解决方案**：
```bash
# 1. 检查端口占用
netstat -ano | findstr :5173  # Windows
lsof -i :5173                 # macOS/Linux

# 2. 强制刷新浏览器
Ctrl + Shift + R (Windows/Linux)
Cmd + Shift + R (macOS)

# 3. 清理构建缓存
npm run clean  # 会删除 dist/ 和 .vite/
npm run dev
```

---

### ❌ Tauri 打包失败

**现象**：`npm run pack` 报错 `Rust toolchain not found`

**解决方案**：
```bash
# 1. 安装 Rust（如果未安装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. 确认安装成功
rustc --version
cargo --version

# 3. 安装 Tauri CLI 依赖（Windows 需要）
# 参考：https://tauri.app/v1/guides/getting-started/prerequisites

# 4. 重新打包
npm run pack
```

**Windows 特殊要求**：
- 安装 Visual Studio Build Tools
- 安装 WebView2 Runtime

## 数据与存储问题

### ❌ 笔记无法保存

**现象**：编辑后刷新页面，内容丢失

**诊断**：
1. 打开浏览器控制台（F12）
2. 切换到 Console 标签
3. 查看是否有红色错误信息

**常见原因与解决方案**：

#### 1. IndexedDB 存储已满
```javascript
// 控制台查看存储使用情况
navigator.storage.estimate().then(console.log)
```
如果 `usage` 接近 `quota`，说明存储已满：
- 删除不需要的附件（特别是大图片）
- 清理浏览器缓存
- 迁移到文件夹模式

#### 2. 浏览器隐私模式
- 隐私模式下 IndexedDB 不持久化
- 退出隐私模式或切换到文件夹模式

#### 3. 文件系统权限不足
（文件夹模式）

检查笔记库文件夹权限：
```bash
# macOS/Linux
ls -la /path/to/notes

# Windows（PowerShell）
Get-Acl "C:\path\to\notes" | Format-List
```

确保当前用户有读写权限。

---

### ❌ 数据丢失或损坏

**紧急恢复步骤**：

#### 浏览器模式
1. **检查历史快照**：
   - 侧边栏 → "历史" → 查看自动快照
   - 选择最近的版本恢复

2. **导出残留数据**：
   ```bash
   # 打开浏览器控制台（F12）
   # 执行以下代码导出 IndexedDB 数据
   ```

3. **重建索引**：
   - 关闭并重新打开快速搜索；全文索引会自动重建
   - 若仍异常，重启应用后再试

#### 文件夹模式
1. **检查手动备份**：
   - 找到你从「笔记树右上角 `⋯` → 备份到 .json」导出的文件（通常在浏览器下载目录）
   - 用同一菜单里的「从备份 .json 恢复」合并回来

2. **Git 恢复**（如果用 Git 管理）：
   ```bash
   cd /path/to/notes
   git log --all --oneline  # 查看历史记录
   git checkout <commit-id> -- <file>  # 恢复单个文件
   ```

3. **系统快照恢复**：
   - Windows：文件属性 → "以前的版本"
   - macOS：Time Machine
   - Linux：`~/.local/share/Trash/` 回收站

---

### ❌ 同步冲突

**现象**：用坚果云/OneDrive 同步后，笔记内容混乱或重复

**原因**：多设备同时编辑同一笔记

**解决方案**：
1. **手动合并冲突文件**：
   - 同步工具通常会生成 `笔记 (冲突副本).md`
   - 手动对比并合并内容

2. **启用锁定机制**（计划中功能）

3. **临时方案**：
   - 设备 A 编辑时，设备 B 不打开应用
   - 或使用 Git 管理（有冲突提示）

## AI 助手问题

### ❌ AI 回复 "API 错误"

**诊断步骤**：
1. 打开浏览器控制台（F12）
2. 切换到 Network 标签
3. 重新发送消息，查看 API 请求

**常见错误与解决方案**：

#### 401 Unauthorized
- **原因**：API 密钥错误或过期
- **解决**：重新填写正确的 API 密钥

#### 429 Too Many Requests
- **原因**：请求频率超限
- **解决**：等待 1 分钟后重试，或升级 API 套餐

#### 500 Internal Server Error
- **原因**：API 服务商故障
- **解决**：稍后重试，或切换到备用 API

#### Network Error / CORS
- **原因**：网络问题或代理配置错误
- **解决**：
  ```bash
  # 检查网络连接
  ping api.openai.com
  
  # 如果用代理，确认代理设置正确
  echo $HTTP_PROXY
  echo $HTTPS_PROXY
  ```

---

### ❌ AI 回答不准确或乱编

**解决方案**：
1. **导入教材 PDF**：
   - 侧边栏 → 设置 → AI 笔记 → 医学教材库 → 导入教材 PDF
   - 导入后在对话中要求"引用教材原文"，回答下方会给出逐字核验徽标

2. **使用更强的模型**：
   - GPT-4 > GPT-3.5
   - Claude 3.5 Sonnet > Claude 3 Haiku

3. **明确要求**：
   - ❌ "讲讲心衰"
   - ✅ "根据《内科学》第 10 版，解释慢性心衰的 NYHA 分级"

4. **核对关键信息**：
   - 药物剂量、诊断标准等务必查阅教材
   - AI 回答仅供参考

---

### ❌ 教材 PDF 导入失败

**可能原因**：
1. **文件是扫描版（没有文字层）**：
   - 检查：用 Adobe Reader 打开，能否复制文本
   - 解决：用设置页里的「用 OCR 导入失败的书」走本地识别（每页约 2~5 秒，单次上限 30 页）；
     页数多的话先用外部工具（如 ABBYY FineReader）识别后再导入

2. **文件读不出来**：换一份未加密、未损坏的 PDF 再试

3. **文件名含特殊字符**：
   - 重命名为纯英文或拼音（如 `neikeXue_v10.pdf`）

**导入后查不到内容？**
- 页码对不上：在教材清单里给这本书填「偏移」——偏移 = PDF 物理页 − 原书印刷页（即前言/目录的页数）

4. **浏览器内存不足**：
   - 关闭其他标签页
   - 重启浏览器后重试

## 性能问题

### ⚠️ 应用卡顿或响应慢

**诊断**：
1. 打开控制台（F12）→ Performance 标签
2. 点击 Record → 操作一会儿 → Stop
3. 查看耗时最长的操作

**常见原因与优化**：

#### 1. 笔记数量过多（> 1000 篇）
- **症状**：打开笔记列表慢
- **解决**：
  - 按文件夹分类整理
  - 归档旧笔记（移到单独的归档库）

#### 2. 单篇笔记过大（> 50KB）
- **症状**：编辑器输入卡顿
- **解决**：
  - 拆分为多篇笔记
  - 移除不必要的大段代码块

#### 3. 图片过多或过大
- **症状**：滚动时卡顿
- **解决**：
  - 压缩图片（推荐用 TinyPNG）
  - 转为外链（如图床）

#### 4. 搜索索引未优化
- **症状**：全库搜索慢
- **解决**：
  - 关闭并重新打开快速搜索，应用会自动重建全文索引
  - 若仍慢，重启应用后再试

---

### ⚠️ 内存占用过高

**检查内存使用**：
```bash
# 打开控制台（F12）→ Memory 标签
# 点击 "Take snapshot" 查看内存占用
```

**优化建议**：
1. 关闭不用的笔记标签页
2. 限制知识图谱显示的节点数（设置 → 图谱 → 最大节点数）
3. 禁用实时预览（设置 → 编辑器 → 关闭预览）
4. 重启应用释放内存

### ❌ Markdown 渲染异常

**示例**：
- 双链 `[[笔记]]` 不高亮
- 代码块不显示高亮
- 公式不渲染

**解决方案**：
1. **检查语法**：
   - 双链：`[[笔记名]]`（注意是两个方括号）
   - 代码块：三个反引号 + 语言名
   - 公式：`$公式$` 或 `$$公式$$`

2. **禁用冲突的浏览器插件**：
   - 某些广告拦截器会破坏渲染
   - 尝试隐身模式（无插件）测试

3. **更新到最新版本**：
   ```bash
   git pull origin main
   npm install
   npm run dev
   ```

### ❌ 面板里滚轮上下都不动（内容超出一屏却滚不动）

**典型表现**：编辑器正文、视频笔记面板这类「面板内部要滚动」的区域，滚轮上下都没反应；
内容也没有真的消失，只是被外层裁掉了。

**先分清是不是代码问题**：`npm run dev` 用 Chrome 打开 `http://localhost:5173`，问题照旧就是前端
布局缺陷；只有在打包版里出现，才去查 WebView2 / 鼠标驱动。

**定位（在控制台粘一次，然后把鼠标放到失效区域滚一格）**：

```js
addEventListener('wheel', (e) => {
  const rows = [];
  for (let n = e.target instanceof Element ? e.target : null; n; n = n.parentElement) {
    const s = getComputedStyle(n);
    rows.push({ el: n.tagName.toLowerCase() + '.' + String(n.className).split(' ')[0],
                overflowY: s.overflowY, scrollHeight: n.scrollHeight,
                clientHeight: n.clientHeight, scrollTop: n.scrollTop });
  }
  setTimeout(() => { console.log('defaultPrevented =', e.defaultPrevented); console.table(rows); }, 0);
}, { capture: true });
```

**判读**：

- 整条祖先链上 `scrollHeight == clientHeight` → **高度链断了**，重点看这一条：
  `.c-edit`（定高 + `overflow:hidden`）→`.note-split`→`.editor-wrap`→`.editor-host`→`.cm-scroller`。
  flex 子项只要有一层没写 `min-height: 0`，它的自动最小尺寸就等于内容高度，于是上面每一层都被撑成
  内容高度，滚动容器自然没有可滚余量。**修复方向：给该层补 `min-height: 0`**，让滚动容器拿到定高。
- 有人 `defaultPrevented = true` 但没有任何 `scrollTop` 变化 → 拦截逻辑自己没滚（`Editor.tsx` 的
  `routeWheel` 只在真的滚动了才 `preventDefault`，是安全的写法）。
- 只有某个嵌套块（代码块、表格）的 `scrollTop` 变了 → `nestedVerticalScroller` 把嵌套块判成可滚区，
  给它的可滚余量加个下限（例如 24px）再判。

**已修过的两处**（改动都在 `src/index.css`）：

| 位置 | 原因 |
|---|---|
| 编辑器正文 | `.note-split` 是块级、`min-height: auto`，被正文撑成内容高度 |
| 视频笔记面板 | 视频与写作区共用一个滚动区；拆成 `.vn__stage`（常驻）＋`.vn__note`（自己滚），每层补 `min-height: 0` |

**验证**：修完再跑上面的片段，应看到「只有一层容器 `scrollTop` 在变、`scrollHeight > clientHeight`」；
再加上 `npx vitest run src/views/__tests__/editorSearchHighlight.dom.test.tsx`（已锁定「正文滚轮滚动
`.cm-scroller`」这条不变量）。

## 3D 解剖图谱问题

### ❌ 3D 模型不显示

**可能原因**：
1. **WebGL 未启用**：
   - 访问 https://get.webgl.org/
   - 如果看到旋转的立方体，说明 WebGL 正常

2. **显卡驱动过旧**：
   - 更新显卡驱动到最新版

3. **浏览器不支持**：
   - 使用 Chrome/Edge/Firefox 最新版
   - Safari 可能有兼容性问题

---

### ⚠️ 3D 渲染卡顿

**优化方案**：
1. 降低模型细节：
   - 右键 → 渲染质量 → "中" 或 "低"

2. 关闭阴影和光照：
   - 设置 → 解剖图谱 → 关闭高级渲染

3. 使用独立显卡（笔记本）

## 测试与开发问题

### ❌ `npm run test` 失败

**解决方案**：
```bash
# 1. 清理缓存
rm -rf node_modules/.vite

# 2. 重新安装依赖
npm install

# 3. 单独运行失败的测试
npm run test -- src/core/__tests__/vault.test.ts
```

---

### ❌ `npm run build` 失败

**常见错误**：

#### TypeScript 类型错误
```bash
# 查看详细错误
npm run build 2>&1 | tee build.log

# 修复后重新构建
npm run build
```

#### 文件路径问题
- Windows 路径用反斜杠 `\`
- 构建脚本中改为 `path.join()` 或 `path.resolve()`
