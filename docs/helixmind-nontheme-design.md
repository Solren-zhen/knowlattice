# HelixMind 非配色设计对照（不改主题）

> 审计对象：`C:\Users\甄朝晖\Desktop\HelixMind-提交\helixmind`
> 对照基线：KNOWLATTICE 当前工作区（`src/views`、`src/styles`、`src/core`）
> 范围：**只谈布局、信息层级、组件形态、交互与响应式**。配色、字体、材质、主题切换不在本文范围。
> 方法：五张成品截图 + 源码结构 + 真实浏览器量测（1440×900 / 390×844）。本次只做了窄屏抽屉定位修复，未改主题；其余为静态结构分析与量测。

## 0. 结论

HelixMind 看起来“更好看”，配色只是一层；真正拉开差距的是五个结构习惯：

1. **一个视图只服务一个主对象**：复习页只有一张卡 + 一个主操作；答题页只有一道题 + 一条底部操作条。
2. **用一级分段导航替代多层面板跳转**：题库、学习统计把“练习 / 错题 / 考试 / 统计”放在同一层，用户不用关面板再开另一个。
3. **操作分层**：主操作固定在底部，导出/导入等低频操作收进「更多」，不跟主任务抢头部。
4. **信息带用 1px 分隔线，而不是嵌套卡片**：KPI、统计摘要是一条带，不是四张卡片。
5. **每个任务流都有明确的下一步**：复习的「显示答案」、错因弹窗的「分析错因 / 跳过 AI」，都把下一步放在动作发生的位置。

KNOWLATTICE 不需要换皮，也不需要把 HelixMind 的每个面板都抄一遍。下面按“改动收益 / 风险”排序，先列可以单独排期的结构改动。

### 可视化提案

- 静态对照页：[非配色设计提案（nontheme-design.html）](./prototype/nontheme-design.html)
- 三个分组：首页首屏 / 题库结构 / 复习任务；左边现状、右边提案，配色沿用当前靛蓝主题。
- 数据为示意，不是真实题库；页面不依赖网络、字体或图片资源。
- 已验收：1440×900 三分组切换正常；390×844 三分组 `docOverflow = -10`（无横向溢出），左右对照自动纵向堆叠。

**HelixMind 证据**

- 截图 `d-dashboard.png`：空态文案是“今天记一次，本周进度就往前走一格”，给的是下一步，不是“暂无数据”。

### P2-2 把“一个主对象 / 一个主操作”写成规则

**HelixMind 证据**

- 复习页：一张卡、一个主操作；答题页：一道题、一个底部操作条；错因弹窗：一个问题、两个动作。
- 统计页：一个标签页承载一类信息，不把六个模块堆成一页。

**KNOWLATTICE 现状**

- 面板数量多，部分面板头部同时承担“返回、导入、导出、设置、关闭”，主操作被挤到卡片中部。
- 新增面板时没有一条“头部最多几个动作”的约定。

**改法**

- 在 `docs/` 增补一节设计约定（不是代码）：
  - 每个整屏面板只能有一个主操作；主操作固定在底部或右下。
  - 头部最多 3 个动作：返回、上下文动作、更多；导出/导入/设置进“更多”。
  - 同一视图只保留一个“主对象”（一张卡 / 一道题 / 一张表），其余是辅助信息。
  - 统计类信息优先用分隔带，不嵌套卡片。
- 在现有 `uiRules.test.ts` 加一条静态检查：整屏面板头部的 `<button>` 数量上限（白名单存量），先挡新增。

**验收**：新面板 PR 头部按钮不超过 3；超过时测试失败并给出白名单说明。

## 5. 建议落地顺序

### 第 1 周：两个低风险结构改动

3. **P0-2 题库一级分段**：先做内部 pane（练习/错题/统计），考试中心暂不合并；验证“不关面板切换”。

### 第 3 周：收口

5. **P2-1 窄屏矩阵**：按面板逐个量 `scrollWidth`，把已修的 `.card.c-insp` / `.card.c-tree` 模式推广。

## 8. 一句话建议

**先做“复习页减负”和“首页首屏重排”这两个不动数据、不动主题的布局改动；题库一级导航放第二步，因为它会碰面板状态。**  
判断标准只有一个：用户能不能在首屏看到“现在该做什么”，以及主操作能不能在固定位置被点到。
