# 3D 解剖资产：换许可源 + 自建管线

> 结论先行：**可行，且许可链完全干净**。但"最好"不等于"零成本"——
> 分割出来的模型是教学可用的，达不到 Z-Anatomy 那种手工精修的程度，
> 两者差在后期美术工时，不在技术路线。

## 一、为什么现成模型都不能用

| 来源 | 许可 | 能否闭源商用 |
|---|---|---|
| BodyParts3D（DBCLS） | CC BY-SA 2.1 JP | ✗ ShareAlike |
| Z-Anatomy | CC BY-SA 4.0 | ✗ ShareAlike |
| Anatria-3D（当前在用） | CC BY-SA 4.0 | ✗ ShareAlike |
| Innerscene 3D Library | **CC0** | ✓ 但只有心脏、泌尿等零星几个，凑不成套 |
| Sketchfab CC0 解剖模型 | **CC0** | ✓ 但单体器官为主、拓扑不统一、命名各写各的 |

关键区别：**CC BY-SA 允许商用**，卡住你的是 SA 的"衍生作品必须同样共享"。
所以需要的不是"免费的模型"，而是"**没有 SA 的模型**"——而这类成套资产基本不存在。

「照着原模型重建」也不行：减面、重拓扑、改配色都不改变"表达来源于它"这个事实，
仍是衍生作品，SA 照样传染。唯一干净的界线是**创作过程中不接触原模型**。

## 二、可行路径：从医学影像重建

器官形状是自然事实，不受版权保护；从影像分割出的几何是你自己的产出。

```
CT/MR 影像  →  器官分割  →  体素掩膜  →  等值面提取  →  平滑/减面  →  GLB
            (TotalSeg)   (int16)     (marching cubes)
```

### 许可链（逐环核过）

| 环节 | 用什么 | 许可 | 商业闭源 |
|---|---|---|---|
| 影像数据 | TotalSegmentator 数据集 v3.0.0（1939 例 CT，37.4 GB） | **CC BY 4.0** | ✓ 署名即可 |
| 分割模型 | `total` / `total_mr` 任务权重 | **Apache-2.0**，官方原文 "Openly available for any usage" | ✓ |
| 重建库 | scikit-image / trimesh / scipy | BSD 系 | ✓ |
| 产出物 | 你自己跑出来的网格 | 归你 | ✓ |

三处必须避开：

- `brain_aneurysm` —— CC BY-NC 4.0，**无商业许可可申请**
- `heartchambers_highres` / `coronary_arteries` / `tissue_types` / `brain_structures` /
  `appendicular_bones` / `face` / `thigh_shoulder_muscles` —— 需向作者单独申请商业许可
- 用公开数据集时，署名写进 `THIRD-PARTY-NOTICES.md`（Wasserthal et al., Radiology AI 2023）

## 三、能覆盖到什么程度

`total` 任务共 117 类。本项目已映射 **95 类到 8 个系统**（`labels.py`）：

| 系统 | 映射类数 | 现有结构数 | 覆盖率 |
|---|---|---|---|
| skeletal | 49 | 335 | 中（椎骨/肋骨/四肢长骨齐全，细分骨没有） |
| cardiovascular | 19 | 640 | 低（8 条主血管 + 心，分支没有） |
| digestive | 9 | 47 | 高 |
| respiratory | 6 | 38 | 高 |
| muscular | 4 | 1110 | 很低（只有竖脊肌群、髂腰肌） |
| renal | 3 | 8 | 高 |
| endocrine | 3 | 10 | 中（甲状腺、双侧肾上腺；垂体/松果体 CT 分不出） |
| reproductive | 2 | 14 | 中 |
| nervous | 0 | 525 | **无**（需 MR + 专门模型） |
| lymphatic | 0 | 142 | **无** |
| articular | 0 | 353 | **无**（软骨/韧带 CT 不可见） |
| regional | 0 | 256 | **无** |

**这不是坏消息**：现有 3478 个结构里，肌肉 1110 + 关节 353 + 神经 525 占了 57%，
而这三类恰好是"辅助功能"场景里最少用到的。教学真正需要的是**内脏 + 主要骨骼 + 大血管**，
这部分覆盖率是高的。

## 四、分阶段计划

### 阶段 0 · 管线验证（已完成）

`scripts/anatomy-build/` 三个脚本 + 合成数据端到端跑通：
掩膜 → 8 万面网格 → GLB（带 NORMAL）→ 浏览器 WebGL 正常渲染。
踩掉三个坑：trimesh 不导法线（黑模）、二值掩膜出台阶、z-up 没转 y-up。

### 阶段 1 · 单例真实数据（约 3–5 天）

1. 装 torch + TotalSegmentator，下载数据集里挑 1 例解剖正常的成年 CT
2. `01_segment.py --fast` 先跑通，再全分辨率重跑
3. `02_mesh.py` 出 4 个系统（消化 / 呼吸 / 泌尿 / 心血管）
4. 接进 `AnatomyViewer3D` 看真实观感，与现有模型并排比对

**判据**：器官轮廓是否可辨认、接缝是否明显、加载时间是否可接受。
这一步的结论决定要不要继续投入。

### 阶段 2 · 多例合并（2–4 周）

单例 CT 得到的是"这个病人的器官"——大小、形态都有个体差异，
直接做产品资产会显得"某个人的肚子"。两条路：

- **选优**：从 1939 例里挑解剖最标准的一例（快，但仍是个体）
- **统计形状**：多例网格配准后取平均（接近解剖图谱，工作量大）

建议先走"选优"，等产品验证了再考虑统计形状。

### 阶段 3 · 补缺口（可选）

- **神经/脑区**：`total_mr` + MR 数据（Apache-2.0 任务，仍可商用）
- **关节软骨/韧带**：CT 造影或 MR，或干脆用示意图
- **肌肉**：需 `thigh_shoulder_muscles` 任务，**要单独申请商业许可**——要么申请，要么放弃

## 五、成本与风险

| 项 | 量级 |
|---|---|
| GPU | 8–12 GB 显存即可（或用云按小时租） |
| 数据 | 37.4 GB（Zenodo，也可只下 102 例的子集） |
| 单例分割耗时 | GPU 约 1–2 分钟；CPU `--fast` 5–10 分钟 |
| 单系统模型体积 | 按 6 万面/器官估算，消化系统约 50 万面 ≈ 3–5 MB（现有为 909 KB，面数更省） |

三个风险：

1. **精细度不如手工模型**。分割边界有锯齿，血管末端会断。上线前大概率需要在 Blender 里
   做一轮重拓扑/平滑——这是美术工时，不是技术问题。
2. **单例偏差**。见阶段 2。
3. **TotalSegmentator 的权重许可措辞可能变**。它是学术项目，README 明确区分了
   Apache-2.0 与"需申请"两类任务。**上线前把当时的 README 存档**，作为许可证据。

## 六、如果只想要最小代价

保留现有 CC BY-SA 模型，但**只在 GPL 社区版里用**；商业版做成"可插拔资产包"——
用户自行导入模型（包括从开源项目下载的 CC BY-SA 资产），产品本身不内置。
责任边界清晰，也是不少商业产品的做法。

代价是开箱体验变差（首次使用要自己找模型）。
