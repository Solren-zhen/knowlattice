## 建议执行顺序

分五批，**批内可并行，批间按序**：

### 批 A — 纯 CSS 小改动（001 → 005）

`001` `002` `003` `004` `005`

每条都是几行 CSS，风险最低，且互不重叠。先做这批能立刻拿到可感知的收益。
建议顺序：`003`（真 bug，最先）→ `001` → `004` → `002` → `005`。

### 批 B — reduced-motion 两条（006 → 007，**必须串行**）

⚠️ `006` 与 `007` 都改 reduced-motion 相关代码，**不要同时执行**，也不要并行交给两个执行者。
先 `006`（新增一个块，纯增量），验证通过后再 `007`（改全局兜底，风险最高）。

### 批 C — JS 改动（008、009、010 可并行）

`008` `009` `010` 分别只碰 `hoverGlow.ts`、`QuizView.tsx`、`BottomSheet.tsx`，互不干扰。

### 批 D — 011（**依赖批 A**）

`011` 的清单已排除 `003` / `004` / `005` 会删掉的那 4 条规则（`4586`、`6484`、`6493`、`6497`）。
**必须等批 A 落地后再做**，否则会搬动即将被删除的规则。计划的第 1 步就是这个前置检查。
